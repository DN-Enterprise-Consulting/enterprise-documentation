# M6.4 – Orchestration Persistence Contract

## Goal

Define the technology-independent persistence SPI for the orchestration aggregate.

## Contract

`OrchestrationPersistence` provides:

- `save(Orchestration)`
- `load(OrchestrationId)`
- `exists(OrchestrationId)`
- `delete(OrchestrationId)`

## Contract semantics

- `save` stores the supplied orchestration.
- `load` returns the persisted orchestration or `null` when no entry exists.
- `exists` reports whether an entry exists.
- `delete` removes the entry when present and is a no-op when absent.

## Boundary rules

1. No file system or database dependency.
2. No framework dependency.
3. No persistence implementation in this milestone.
4. The SPI depends only on the orchestration domain.
5. The contract is verified using a minimal test double.

## Non-goals

- file-based persistence
- repository integration
- runtime composition
- service layer
- cross-domain orchestration execution
