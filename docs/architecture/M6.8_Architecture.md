# M6.8 – Orchestration Query / Retrieval

## Scope

M6.8 introduces a dedicated query boundary for retrieving orchestrations without coupling callers to repository implementation details.

## Components

- `OrchestrationQuery`: immutable optional filters for type and status.
- `OrchestrationQueryService`: repository-SPI based retrieval service.

## Query semantics

- `all()` – no filters.
- `byType(type)` – filter by orchestration type.
- `byStatus(status)` – filter by orchestration status.
- `byTypeAndStatus(type, status)` – both filters are applied with AND semantics.
- A null query is rejected.
- Null Optional values supplied to the record constructor are normalized to empty filters.

## Boundary

The query service depends only on `OrchestrationRepository` from the orchestration SPI. It does not depend on file persistence or concrete repository implementations.

## Non-goals

M6.8 does not introduce cross-domain execution, step execution, workflow integration, assessment/rules/knowledge/publishing coupling, or web/API concerns.
