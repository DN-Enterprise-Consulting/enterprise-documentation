# M7.1 – Execution Domain Foundation

## Purpose

M7 introduces the executable cross-domain layer. M7.1 establishes the framework-free domain foundation for an execution instance.

## Scope

Implemented:

- `ExecutionId`
- `ExecutionType`
- `ExecutionStatus`
- `ExecutionMetadata`
- `Execution`

Lifecycle:

`DRAFT -> RUNNING -> COMPLETED`

or:

`DRAFT -> RUNNING -> FAILED`

`COMPLETED` and `FAILED` are terminal states.

## Boundary

The execution domain does not depend on:

- Assessment
- Rules
- Knowledge
- Publishing
- Workflow
- Orchestration runtime implementations
- persistence technologies
- web frameworks

M7.1 therefore does not execute any domain work yet.

## Design

`Execution` is immutable. State transitions create new instances.

Execution metadata may only be changed while the execution is `DRAFT`.

Execution steps, execution context, execution results and domain adapters are deliberately deferred to later M7 milestones.

## Dependency direction

`execution -> shared-kernel`

No reverse dependency is introduced.

## Definition of Done

- Java 21 compatible
- framework-free domain model
- immutable records
- explicit lifecycle
- null/invariant validation
- unit tests
- Maven reactor integration prepared through the new `execution` module


## Build correction

The execution module imports `platform-bom` in its own `dependencyManagement` section so that
JUnit Jupiter and AssertJ versions are inherited consistently with the existing platform modules.
The root Maven POM remains free of a platform-bom import to avoid the established parent/BOM cycle.
