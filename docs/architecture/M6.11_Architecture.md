# M6.11 – Orchestration Application / API Boundary

## Scope

M6.11 introduces the stable application boundary for the orchestration domain.
The application layer exposes orchestration use cases without requiring callers
to construct persistence infrastructure directly.

## Application boundary

`OrchestrationApplication` exposes:

- create
- get
- findAll
- findByType
- findByStatus
- query
- updateMetadata
- start
- complete
- fail

The application boundary delegates domain use cases to
`PersistentOrchestrationService` and retrieval filtering to
`OrchestrationQueryService`.

## Runtime integration

`OrchestrationRuntime.fileBacked(Path)` now composes:

`FileOrchestrationPersistence -> FileOrchestrationRepository -> services -> OrchestrationApplication`

The existing `orchestrationService()` accessor remains available for compatibility.
`application()` is the preferred entry point for callers.

## Architectural constraints

- No HTTP, REST, Spring or framework dependency is introduced.
- Application code does not construct persistence adapters.
- Domain and SPI layers remain unchanged.
- Query filtering remains delegated to the query service.
- Cross-domain execution of Assessment -> Rules -> Knowledge -> Publishing is explicitly out of scope for M6.11.

## Definition of Done

- Stable application facade exists.
- CRUD, query and lifecycle use cases are exposed.
- Runtime composes the application boundary.
- Existing runtime behavior remains available.
- Application boundary tests pass.
- Full Maven reactor verification is green.
