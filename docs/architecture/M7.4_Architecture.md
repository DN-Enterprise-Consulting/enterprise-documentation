# M7.4 – Assessment Step Executor

## Purpose

M7.4 introduces the first concrete domain adapter. The execution layer can now execute an Assessment step without depending on Assessment repositories or lifecycle internals.

## Implementation

`AssessmentExecutionAdapter` implements the M7.3 `ExecutionAdapter` SPI and delegates Assessment use cases exclusively through `AssessmentApplication`.

The adapter:

1. reads the required execution context values
2. creates an Assessment through the application boundary
3. starts the Assessment
4. completes the Assessment
5. returns the resulting Assessment ID, type and status as execution outputs

## Context contract

Required keys:

- `assessment.type`
- `assessment.name`
- `assessment.description`

`assessment.type` must match a supported `AssessmentType` enum value.

## Output contract

The successful result contains:

- `assessmentId`
- `assessmentType`
- `assessmentStatus`

## Dependency direction

`execution -> assessment -> shared-kernel`

The adapter depends on the stable Assessment application API, not on Assessment persistence or repository implementation classes.

The execution SPI remains usable independently of Assessment.

## Scope

This milestone does not implement:

- Rules, Knowledge or Publishing adapters
- adapter registry composition
- execution engine
- retry/recovery
- execution persistence
- end-to-end orchestration

Those responsibilities remain in later M7 milestones.

## Definition of Done

- concrete Assessment adapter
- application-boundary integration
- explicit context contract
- execution result contract
- tests proving Assessment creation and completion
- no direct repository use by production adapter
