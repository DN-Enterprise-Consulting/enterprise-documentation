# M6.3 – In-Memory Orchestration Repository

## Goal

Provide the first concrete implementation of the M6.2 `OrchestrationRepository` SPI.

## Implementation

`InMemoryOrchestrationRepository` uses a `ConcurrentHashMap` keyed by `OrchestrationId`.

Supported operations:

- save
- findById
- findAll
- findByType
- findByStatus
- existsById

## Design rules

1. The implementation depends on the orchestration SPI and domain only.
2. Storage is process-local and non-persistent.
3. `save` returns the supplied orchestration.
4. Saving an existing ID replaces the previous aggregate.
5. Query results do not expose the mutable backing collection.
6. Null arguments are rejected explicitly.
7. The implementation is thread-safe through `ConcurrentHashMap`.

## Non-goals

- file/database persistence
- service/runtime composition
- lifecycle handling
- cross-domain orchestration execution
