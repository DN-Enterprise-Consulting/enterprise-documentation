# M6.5 – File-Based Orchestration Persistence

## Goal

Provide a deterministic file-based implementation of the M6.4 persistence SPI.

## File format

Files use the `.orchestration` extension and UTF-8 encoding.

Each aggregate is stored as seven lines:

1. orchestration UUID
2. orchestration type
3. orchestration status
4. metadata name
5. metadata description
6. metadata attributes
7. ordered orchestration steps

Values are Base64 encoded. Metadata attributes are sorted by key before serialization.

## Behavior

- storage directory is created automatically on save
- missing files return `null` from `load`
- `delete` is idempotent
- corrupt files raise `OrchestrationPersistenceException`
- null arguments are rejected
- step ordering is restored deterministically

## Boundary rules

The implementation depends only on the orchestration domain and persistence SPI.
No database, framework, or external service is introduced.

## Non-goals

- persistent repository integration
- service/runtime composition
- lifecycle service
- cross-domain execution
