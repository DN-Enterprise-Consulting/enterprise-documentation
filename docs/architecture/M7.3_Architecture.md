# M7.3 – Domain Adapter SPI

## Purpose

M7.3 establishes the stable SPI between the execution layer and domain-specific execution adapters.

## Components

### ExecutionAdapter

The adapter exposes:

- a stable `domainKey()`
- an `execute(ExecutionContext)` operation returning an `ExecutionResult`

The execution layer therefore depends on an abstraction rather than concrete Assessment, Rules, Knowledge or Publishing implementations.

### ExecutionAdapterRegistry

The registry resolves adapters by domain key and exposes all registered adapters.

Unknown domains are rejected by `requireByDomainKey`.

## Boundary

The SPI does not depend on:

- Assessment implementation classes
- Rules implementation classes
- Knowledge implementation classes
- Publishing implementation classes
- Orchestration implementation classes
- persistence technologies
- web frameworks

Concrete adapters will be introduced in M7.4–M7.7.

## Domain keys

The SPI deliberately treats domain keys as strings at this stage. Concrete adapters will establish the canonical keys when their corresponding domain integration is implemented.

The M7.3 milestone therefore does not invent or hard-code the four domain integrations prematurely.

## Execution semantics

The SPI passes `ExecutionContext` into an adapter and receives `ExecutionResult` back.

Context mutation and result persistence remain outside the adapter SPI.

## Definition of Done

- framework-free SPI
- no dependency on concrete domain implementations
- adapter resolution abstraction
- explicit unknown-domain behavior
- unit tests using test doubles
- architecture documentation
