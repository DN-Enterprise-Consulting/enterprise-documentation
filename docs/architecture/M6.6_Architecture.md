# M6.6 – Persistent Orchestration Repository Integration

## Goal

Integrate the M6.5 file persistence implementation with the `OrchestrationRepository` SPI.

## Components

- `FileOrchestrationRepository` implements `OrchestrationRepository`.
- `FileOrchestrationPersistence.loadAll()` provides deterministic enumeration of `.orchestration` files.
- Repository filtering is implemented by orchestration type and status.
- Repository recreation against the same storage directory verifies persistence across process/runtime boundaries.

## Repository behavior

- `save()` persists and returns the supplied aggregate.
- `findById()` maps missing persistence results to `Optional.empty()`.
- `findAll()` returns all persisted orchestration aggregates.
- `findByType()` and `findByStatus()` use the repository's aggregate collection and apply exact enum matching.
- `existsById()` delegates to persistence.
- Saving an existing ID replaces the persisted aggregate.
- Null arguments are rejected.

## SPI boundary

The generic `OrchestrationPersistence` contract remains unchanged in M6.6. Because it does not yet expose `loadAll()`, `findAll()` uses an explicit `instanceof FileOrchestrationPersistence` boundary, matching the transitional repository pattern already established in the platform.

## Non-goals

- service/runtime composition
- lifecycle management
- validation integration
- cross-domain execution
- changes to the generic persistence SPI
